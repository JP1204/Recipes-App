# Recipes App

A small SwiftUI + SwiftData iOS app for tracking your family's pantry and recipes, and answering "what can I make right now?"

## Features (v1)

- **Pantry tab** — list every pantry item, add custom items, swipe to delete, search by name.
- **Recipes tab** — list your recipes, create one with as many ingredients as you want, view a detail page that checks each ingredient against the pantry, swipe to delete.
- **What Can I Make? tab** — splits recipes into "Can Make Now" (every ingredient is in the pantry) and "Almost There" (missing 1 or 2 ingredients, with the missing items called out).

Matching is case-insensitive exact-name (whitespace trimmed). So "Flour" in the pantry matches "flour" in a recipe.

## Requirements

- macOS with **Xcode 15 or later** (SwiftData needs iOS 17+)
- Targets **iOS 17.0+**
- iPhone / iPad simulator, or a real device with a free Apple Developer account for signing

## How to open

1. Double-click **`RecipesApp.xcodeproj`** in this folder. Xcode should open the project.
2. At the top, pick a simulator (e.g. iPhone 15) from the device dropdown.
3. Hit the **Run** button (▶) or press **⌘R**.

If Xcode complains about code signing, click the project file in the sidebar → **RecipesApp** target → **Signing & Capabilities** → set **Team** to your Apple ID (it'll appear once you've signed into Xcode under Settings → Accounts). You may also want to change the **Bundle Identifier** from `com.example.RecipesApp` to something unique like `com.<yourname>.RecipesApp`.

## If the project won't open

The `project.pbxproj` was generated by script. If Xcode rejects it for any reason, create a fresh project and drop the source files in — it takes about a minute:

1. Xcode → **File → New → Project…**
2. Choose **iOS → App**, click Next.
3. Product Name: `RecipesApp`, Interface: **SwiftUI**, Language: **Swift**, Storage: **SwiftData**, then Next and save it somewhere temporary.
4. Delete the auto-generated `ContentView.swift`, `Item.swift` (if present), and `<Name>App.swift` files (right-click → Delete → Move to Trash).
5. Drag **every `.swift` file from this folder's `RecipesApp/RecipesApp/` directory** into Xcode's project navigator. When prompted, make sure **"Copy items if needed"** is checked and the **RecipesApp target** is ticked.
6. Build & run with **⌘R**.

## Project layout

```
RecipesApp/
├── RecipesApp.xcodeproj/
└── RecipesApp/
    ├── RecipesAppApp.swift       — @main entry, sets up the SwiftData ModelContainer
    ├── ContentView.swift         — root TabView
    ├── PantryItem.swift          — @Model: a pantry item
    ├── Recipe.swift              — @Model: a recipe (cascades to ingredients on delete)
    ├── RecipeIngredient.swift    — @Model: one ingredient inside a recipe
    ├── PantryMatcher.swift       — pure functions for normalizing names + finding missing ingredients
    ├── PantryView.swift          — Pantry tab
    ├── AddPantryItemView.swift   — sheet to add a pantry item
    ├── RecipesView.swift         — Recipes tab
    ├── RecipeDetailView.swift    — single-recipe detail
    ├── AddRecipeView.swift       — sheet to create a recipe
    └── SearchView.swift          — "What Can I Make?" tab
```

## Notes for the developer

- The matching logic lives in `PantryMatcher.swift` — when you want to make matching smarter (plurals, "olive oil" vs "extra virgin olive oil", etc.), that's the place.
- `SearchView` recomputes matches on every render. With small data this is fine; if you start having hundreds of recipes, cache `pantryNames` and missing lists.
- `Preview` providers use `inMemory: true` so SwiftUI previews don't pollute on-disk data.
